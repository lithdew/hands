# Hands media worker

This trusted worker accepts a bounded JSON storyboard from the Hands specialist and renders a playable H.264 MP4 with Remotion. Matrix scenes are generated by **3b1b's ManimGL**, rather than imitating its visuals. The user said "3Blue1Brown's tool"; interpreting that as ManimGL is an explicit assumption. No model-supplied Python, JavaScript, shell commands or remote media are executed.

## Setup

From this directory, run `bun install --frozen-lockfile`. From the repository root, create a Python environment at `out/media-python` using Python 3.12, then install `workflows/media/requirements.txt` into it. This leaves dependencies in ignored local paths. ManimGL uses the machine's OpenGL driver; LaTeX is not required by the numeric scene. FFmpeg comes from the pinned imageio-ffmpeg wheel. Remotion downloads its isolated headless renderer browser automatically; it never attaches to the user's signed-in Chrome.

```
python -m venv out/media-python
out/media-python/Scripts/python.exe -m pip install -r workflows/media/requirements.txt
bun workflows/media/render.ts out/run/storyboard.json out/run/media
```

The renderer exports `renderStoryboard(specPath, outputDir, options?)`. `options.evidenceAssets` is a trusted map of short ids to PNG/JPEG files under repository `out/`. A model can select a supplied id via `scene.artifactImage`; it cannot choose local file paths. The calling workflow must limit that map to public-safe, inspected artifacts from authorized runs. Neither path confinement nor valid image bytes establish privacy by themselves.

Pass the task's `AbortSignal` as `options.signal`. Each render runs in a separate supervised worker; Windows assigns that supervisor to a new job before it launches children. Cancellation first cancels Remotion and subprocesses, then closes only that render's owned process tree after a five-second grace period if a library remains stuck. It never selects a process by name or attaches to account Chrome. The default whole-render deadline is 15 minutes; `options.timeoutMs` can select a bound from 100ms to 30 minutes. Individual subprocesses also have deadlines and bounded log capture. CLI Ctrl+C forwards the same cancellation.

`storyboard.ts` is the exact schema. The model writes `version:1`, `title`, `kind` (`matrix-inversion` or `pitch`), `scenes`, and `sources`. Scenes contain `id`, `title`, `visual`, `durationSeconds` (3–30), plus optional `body`, `bullets`, `caption`, `narration`, `evidence`, `matrix`, `artifactImage`, `artifactLabel`. A matrix is a numeric 2×2 array with entries in [-5,5]. Supported visuals: title, bullets, matrix, evidence, closing. Sources are public HTTP(S) URLs. `evidence` entries are `{label,value,source}`; the source string is displayed as attribution, not fetched.

## Legibility contract

Frames are 1280×720 but are also watched inside a 390px-wide phone page, where the whole frame is about 360px wide. The composition therefore sets copy large (headings 48–72px, body 30–38px, bullets 28–36px, captions 26px, matrix entries 38px) in a single content lane above a reserved caption band, and `storyboard.ts` enforces per-scene text budgets before rendering: titles ≤60 characters, body ≤170 (≤120 beside an animation), at most 4 bullets of ≤90 characters (3 of ≤64 beside an animation), captions ≤130, ≤420 characters of title+body+bullets per scene (≤300 for matrix scenes) and at least a quarter second of reading time per word. The Hands workflow runs that schema as the `storyboard-schema` check before the content review, so an overloaded storyboard returns to the specialist instead of failing the render. Inline `[[a,b],[c,d]]` notation in titles, body and bullets is typeset as a two-row matrix; the trusted matrix panel is labelled with the letter the copy uses (`matrixName`, else the `X = [[` letter, else A). Copy that still overflows its lane is scaled as one unit down to 80%; beyond that the render is refused rather than clipped or shrunk below phone legibility.

Evidence scenes with an image show the unchanged image in a wide panel for the first 62% of the scene, then show all supplied body, bullets and evidence records in a separate readable panel. The midpoint still captures the artifact; reviewers should also inspect the final evidence phase. Image content is never automatically cropped. A focused, faithful screenshot can be provided through the trusted asset map with its own provenance. Oversized headings or evidence text fail the render instead of being clipped or reduced below the layout's minimum scale.

Burned-in captions reserve a band above desktop player controls (`CAPTION_TOP` in `layout.ts`) at 26px with a two-line limit. The scene copy, geometry and evidence panels end above that band. A narrow inline player still needs the generated page's readable scene notes and fullscreen affordance. Contact-sheet annotation labels use a local TrueType font when one is available and fall back to ASCII for Pillow's portable font; the actual movie frames retain their original text and glyphs.

On Windows, optional narration uses local System.Speech (SAPI) and extends the scene if needed. Without narration, the manifest explicitly records a silent captioned video. Narration is synthetic, never a cloned person's voice. Fixed output is 1280×720 at 24 fps. The spec can include those dimensions explicitly or omit them.

## Output and verification

Outputs: `video.mp4`, `contact-sheet.png`, one scene midpoint PNG under `frames/`, `subtitles.srt`, normalized storyboard, render manifest, and actual Manim clips under `assets/`. The manifest records source URLs, render timings, hashes, engine versions, matrix determinants/inverses, exact media metadata, and full FFmpeg decode success. **These checks do not prove visual quality, mathematical exposition or truthful claims.** A reviewer must inspect the contact sheet/video and compare copy to the sources and artifacts. The manifest leaves visual inspection pending.

`render-status.json` records running, complete, cancelled, failed or timed_out. Cancelled/failed runs preserve partial files for inspection and never publish `render-manifest.json`; a manifest caught during finalization is retained as `.incomplete` with its validation result discarded. Every retry must use a new output directory. Completion is emitted only after the worker exited successfully, cancellation was checked, and the verified manifest was published.

Fast cancellation/ownership tests run with `bun test workflows/media/process.test.ts workflows/media/render.test.ts`. Set `HANDS_MEDIA_INTEGRATION=1` to also exercise actual cancellation during bundling, rendering and verification, plus a successful tiny MP4 render. These tests use isolated render browsers and no account UI.

The worker refuses an existing output directory, paths escaping repository `out/`, unknown spec fields, arbitrary media references, missing evidence images, malformed matrices and overlong videos. It uses an isolated Remotion renderer browser and never calls Hands, Chrome account APIs or external services. All model reasoning, task selection and Jev return decisions happen in the parent Hands workflow.

Primary API sources: [ManimGL project](https://github.com/3b1b/manim), [ManimGL CLI](https://3b1b.github.io/manim/getting_started/configuration.html), [Remotion bundle](https://www.remotion.dev/docs/bundler), [selectComposition](https://www.remotion.dev/docs/renderer/select-composition), [renderMedia](https://www.remotion.dev/docs/renderer/render-media).
